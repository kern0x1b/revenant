# CoreSpotlight: CharonCoreSpotlightProtocols.h

## CharonCoreSpotlightProtocols.h

The header is generated by `xmake l tools/gen.lua protocols` from `spec/CoreSpotlight/protocols.tsv` and
`spec/protocol-headers.tsv`. The comments the committed header carried, in its order, are kept here:

```text
CharonCoreSpotlightProtocols.h - the CoreSpotlight protocols the generated protocol sources name, written by
xmake l tools/gen.lua protocols. One the SDK this package compiles against already defines, or a
header of this folder does, is forward-declared and its body comes from that import; any other is
transcribed from the SDK that declares it: the base list, each member with its kind and types,
@required and @optional as sections, and API_AVAILABLE(ios(<introduced>)). Facts only.
This file has a forward-declared protocol in it, so it imports <CoreSpotlight/CoreSpotlight.h> for that body, and
```

`CSSearchableIndexDelegate` (iOS 9.0) is the one protocol of the framework that carries a registry row, and the SDK this
package compiles against declares it, so the header forward-declares it and imports the SDK's CoreSpotlight header for the
body. The generated protocol source defines the runtime protocol for the release that lacks it (iOS 6.1.3), as the
registry's implemented row says.
