# air2es notes

air2es translates the render stages of a Metal library (AIR bitcode) into GLSL ES 1.00
folders that the Metal backport loads. This file records what is known to be missing
and why, so it is not rediscovered later.

## Measured on Telegram's default.metallib (macOS air64, 15 modules)

- 12 of 14 render functions translate, pass the Appendix A checker, and pass
  glslangValidator in ES mode: basic_vertex, edgeTestVertex, matrixVertex,
  post_vertex_main, twoInputVertex, vertexPassthrough, edgeTestFragment, fragmentPlain,
  basic_fragment, scaleAndBlur, transformAndBlend, fragmentColorConversion.
- matrixFragment is refused by name: its sampler has a linear mipmap filter, and a
  translated texture has no mipmaps on GLES 2.
- post_fragment_main is refused: its nested loop re-enters an earlier block, and the
  structurer lowers only counted cycles (see Control flow). This comes from reading the
  CFG, not from a run.
- compute_main is a kernel and translates to a 14,597-line GLSL ES kernel, because its
  helpers are inlined at each call site. glslangValidator accepts it in ES mode. It
  needs the constexpr cube sampler and two counted loops with breaks.

## Constexpr samplers

- A constexpr sampler is an `i64` global named by `air.sampler_states` metadata, and a
  sample reads it through a pointer to that global, not through an argument.
  `samplerStateOf` in `translate.cpp` reads it, and `air2es --samplers METALLIB` prints
  the state of each function, so the table generator reads it the same way.
- The state is decoded by lookup in `samplers.inc`, generated by
  `tools/metal_sampler_table.lua` from the Metal compiler of Xcode 27B47. The table is
  for the iOS target, and it has 795 states. A state outside the table is refused by
  name, as is each part GLES 2 cannot express: mirrored repeat, a clamp-to-zero address
  whose minification and magnification filters differ (the level of detail that picks one
  is not computed), a cube sample with a clamp-to-zero address, a mipmap filter, pixel
  coordinates, anisotropy and, on iOS, a LOD clamp above zero (the macOS nine-operand form
  is in its own section below). A clamp-to-zero address with one
  filter is emulated, see "Clamp-to-zero samples" below. A plain sample does
  not read the compare function, so a constexpr compare is not refused.
- The generator needs the toolchain's `metal` and `metallib`. The image is pinned in
  `tools/metal_toolchain.lua`. Run it with
  `./xmakew l frameworks/Backports/tools/metal_sampler_table.lua DMG build/macosx/arm64/release/air2es src/air2es/samplers.inc WORKDIR [MOUNT]`.
  DMG may be empty, and then `REVENANT_METAL_TOOLCHAIN_DMG` names the image. Pass MOUNT
  when the image is already attached read-only, because a second attach of the same
  image is refused.
- The table's rows are checked against the Telegram constants 0x807bff0000080a49 and
  0x807bff0000084a92: the generator stops if the compiler does not produce them.
- The reflection of a texture carries the decoded wrap and filter. The loader applies
  them at each draw, because a constexpr sampler has no MTLSamplerState to bind.
- The iOS target declares no border colour, so `clamp_to_border` does not compile for
  iOS and the table has no border field.

## macOS sample_texture_2d

- The macOS form (`air64-apple-macos13.0`) of a sample is `air.sample_texture_2d.v4f32` with nine operands: texture, sampler
  state, coordinate, normalized, offset, hasLod, level or bias, min_lod_clamp, access. It returns `{ <4 x float>, i8 }`. The
  iOS form has eight operands, with no min_lod_clamp, and returns `<4 x float>`.
- The operand order and types are those of `__metal_sample_texture_2d_t` in the Metal toolchain's header
  `metal/__bits/metal_texture2d`.
- `sampleLocal` (`translate.cpp`) holds the colour element. The translated form needs min_lod_clamp to be the constant 0.0 and
  access to be 0 (sample); other values are refused by name. The i8 residency element is refused if it is used.
- `metal_shader_harness` reads each texture's wrap and filter from the reflection (`filterOf`, `wrapOf`) and sets them as the
  GL texture parameters, so the GLES sample uses the same sampler state as the constexpr one. A linear GLES sampler does not
  pass for a nearest constexpr one.
- Fixture: `tests/air2es/sample_mac.metal`, `sample_mac.metallib` and `sample_mac.golden/`. The harness matches Metal on
  `sampleFragment` with a max diff of 0 over 13,312 non-zero channels.

## Oracle data source and device buffers

- `metal_shader_harness METALLIB FOLDER [ANGLE_LIB [DATA_JSON]]` takes an optional data source, a JSON object with two keys.
  `arrays` holds a device buffer's elements, flat, by the Metal argument's name (`"positions": [...]`). `members` holds a
  uniform's values by its name, for both sides (`"viewport": [x, y, z, w]`). Without a data source the values are the fixed
  ones of the earlier harness.
- With `REVENANT_DUMP` set to a folder, the harness writes each run's Metal and GLES pixel buffers there as `<vertex>+<fragment>-<ints>-metal.rgba`
  and `-gles.rgba`, 4 bytes per pixel, for a diff of a failing run.
- A device pointer is filled element by element at its Metal stride. The GLES element uniform `<name>_<k>`, which the
  translator emits for a capped buffer, takes element k of the same array. Its GLES offset must equal k times that stride, or
  the run FAILs with a layout line.
- The harness sets `revenant_target` to the target's size, as the host does (`RevenantMetalEncoder.m`). A fragment that reads
  `[[position]]` matched only after this; before it, the GLES side computed `0 - gl_FragCoord.y`.
- Fixture: `tests/air2es/devbuf_mac.metal` (`callBlobVertex` reads a `const device float *positions` buffer, capped at eight
  elements; `blobFragment` reads `viewport` from a constant struct) and its `devbuf_mac.metallib`. Data sets:
  `devbuf_one.data.json` (viewport z and w 1), `devbuf_mid.data.json` (0.5) and `devbuf_zero.data.json` (0). Results: one PASS
  over 1,044 non-zero channels, mid PASS, zero PASS over 261 (alpha only). Negative control: the Metal source reads
  `positions[vid % 5]` against the GLES folder of `vid % 7`: FAIL, 255/255 over 592 channels.
- The earlier Mac fixtures (`deriv_mac`, `exit_mac`, `sample_mac`) and the GramDiamond composite give the same numbers as before.
- Not covered: vector elements (the diamond's `planes` are `float4`), since the translator has no vector-element cap in HEAD yet,
  and a `max` viewport for the lens's 128 edges. Both need the translator's capped-buffer patch before there is a GLES side.

## Runtime-bounded loops and vector buffer elements

- A counted loop whose latch compares the index with a value defined outside the loop is emitted as a `for` to the host cap of a
  capped buffer that the body indexes with the loop index (`latchCycleOf`, `loopCapOf`). The latch test stays in the body, so the
  loop stops at the uniform's count (`if (t17 == t0) break;`); a zero count is the guard before the loop. A loop with no capped
  buffer behind its index stays refused.
- A loop whose body is one block, which is both header and latch, is recognised with a runtime bound. A constant-bound
  self-loop keeps its earlier route through `loopOf`: the first attempt changed four `gaussianBlur` kernels from OK to REFUSED,
  and the corpus check caught it.
- A host-capped buffer of `float2`, `float3` or `float4` elements is one uniform per element, as the scalar ones are
  (`binding.stride` must equal the element size). `float3` is not tested.
- Fixture: `tests/air2es/loop_mac.metal`, whose `loopFragment` loops `uint(viewport.z)` times over a `float4` buffer capped at
  eight, and exits with the last index as a phi. Its capped buffer is named in `kBufferCaps` (`loopFragment`, `planes`, 8), as
  `callBlobVertex` is. The diamond's entries (planes 17, edges 128) and the select limit of 128 are not in this change: they
  change the diamond's verdicts, and they come with the geometry data source.
- Oracle: `loop_z0`, `loop_z1`, `loop_z3` and `loop_z8` (the data sets, in `tests/air2es/`) PASS, max channel diff 0 over 16,384
  channels each. The negative control, Metal `i + 1 < z` against the GLES folder of `i < z`, at z = 3, FAILs at 25/255 over 4,664
  channels.

## Corpus check

- `./xmakew l frameworks/Backports/tools/metal_corpus.lua DMG build/macosx/arm64/release/air2es REFERENCE OUT.tsv [MOUNT]`
  compiles the Metal sources of a Telegram checkout to iOS AIR, links them per
  directory, translates each library and writes one verdict per entry point.
- On Telegram-iOS-release-13.0.0 it gives 89 entry points: 43 fragment, 27 vertex and
  19 kernel. 66 translate (32 fragment, 23 vertex, 11 kernel) and 23 are refused, measured after the `air.point_size` and `air.any` change and the host element cap of
  `callBlobVertex`, which follows the half-precision change, the switch change, the bounded integers and the clamp-to-zero
  emulation; `docs/explanation/backports/air2es-ios-verdicts.md` has the
  history.

## Precision and device checks still owed

- Fragment shaders use `precision mediump float;`, as the loader contract requires.
  The `fmod` lowering (`x - y * sign(q) * floor(abs(q))`, with `q = x / y`) runs its
  quotient at mediump, so large quotients can lose integer precision. Check it on a
  device.
- The blur accumulators (scaleAndBlur, transformAndBlend) are vec4 sums of 61 samples
  at mediump. Check the result against the Metal output on a device.
- The `[[position]]` flip (`y = revenant_flip > 0 ? target.y - gl_FragCoord.y :
  gl_FragCoord.y`) is derived from the encoder's flip logic and is not verified on a
  device.

- The bounded division and remainder (`revenant_quotient`, `revenant_remainder`) need a device float division with a relative
  error up to 2^-18, and results up to 2^22 in highp int, which ES 1.00 guarantees only at 16 bits. The float check covers
  the first. The ES 2 probe's `udiv_u_i32` and `urem_u_i32` maps check both on the 4S, and the run is owed for the
  regenerated artefact.

## Design choices

- A constant table read at a variable index becomes a select chain over its entries.
  An index outside the table takes the last entry. LLVM calls that case undefined, so
  the choice is ours.
- A variable read from an empty constant table is refused by name.
- A buffer read at the instance id is read as uniforms of that instance's element: the uniform carries
  `instanceStride` set to the element size, and the host offsets it by the instance of each draw. A dynamic index into an
  array member of a buffer is a select chain over one uniform per element, as for a constant table. The instance probe
  checks both on the 4S through the Metal backport.
- A square float matrix member (`float2x2`, `float3x3`, `float4x4`) is one `uniform matN`. A load of a column, or of a lane
  of one, becomes an index into it. Metal pads a column of a float3 matrix to four floats, so the host packs only the three
  floats of each column for `glUniformMatrix3fv`. The instance probe checks the column-major product on the 4S against a
  host reference, and a transposed upload must fail the same reference.
- A read of a texture at the thread position is a nearest fetch of the texel centre, with the size from the host. A
  logical shift right of a thread position, or of one of its lanes, by a constant is an integer division by 2^k. The
  texture stage of the ES 2 probe checks both on the 4S: exact for the sizes it runs, which are up to 1024 by 1024.
- Internal helper functions are inlined at each call site. They are not emitted as GLSL
  functions, so their sampler and texture parameters map to the caller's bindings.
- A buffer argument with an element count that the host declares (`kBufferCaps` in `translate.cpp`). A scalar pointer
  argument read at a dynamic index becomes one uniform per element, and the index is a select chain over them, as for an
  array member of a buffer struct. The count is a host contract taken from the host's code, and neither the shader nor the
  loader checks it: the loader reads each element's bytes at its offset, so a host that sets fewer bytes reads past them.
  Only `callBlobVertex` has an entry (`positions`, 8 elements; `CallScreen/Sources/Components/CallBlobsLayer.swift:113`).
- Control flow: an if/else region ends at the branch's immediate post-dominator. Phi
  values are copied on each edge, through temporaries when an edge copies more than one
  phi.
- A loop is lowered only when it starts at a constant, steps by one and exits when
  `index + 1` equals a constant. It becomes `for (int i = start; i < bound; i++)`.
  Two shapes qualify. A single block that branches to itself. Or a header whose
  conditional branch enters a latch that branches back to the header and exits on the
  same block as the header. In the second shape each edge that leaves the loop is a
  `break` after its phi copies, the back edge is the phi copies of the iteration, and a
  join outside the loop is the header. Any other loop is refused by name.
- Clamp-to-zero samples. A sample of a texture whose constexpr sampler has a clamp-to-zero address is a
  function of the texture's size, so the translated shader carries `<texture>_size` (the host sets it) and
  a helper per texture and sampler shape: `revenant_tap_<tex>_<axes>` fetches one texel centre with nearest,
  multiplied by a 0/1 mask per clamp-to-zero axis, and `revenant_sample_<tex>_<filter><axes>` is the
  nearest fetch, or the four-tap bilinear weights of Metal's linear filter. The host binds nearest and
  clamp-to-edge for the texture, and the shader does the wrap or the clamp, so no non-power-of-two repeat
  reaches the driver. Cube samples with clamp to zero are refused. The emulation is measured on the Mac
  against Metal (`metal_shader_harness`); the nearest filter and the repeat axis are not measured by any
  corpus entry, and they stand on the same helper.
- Bounded integers. A division or remainder of two non-negative integers, a shift left by a constant and a logical shift
  right by a constant are computed in float, and each is refused unless its operands have a known bound. A bound is known
  for a constant, a vertex id, a buffer member, and a float converted to an unsigned integer. An instance id has no bound:
  DustEffect draws one instance per particle, and the count is the item's width times height in points, above 2^16 on the
  4S, so `dustEffectVertex` is refused. The host's vertex ids, buffer members and converted floats are taken below 2^16: a
  host contract the shader does not check, with the Telegram values and their citations in the verdict doc's bounded-integers
  section. A division takes operands below 2^16 and corrects its float quotient by one step from the exact remainder, so the
  result is exact. A divisor of zero is undefined in LLVM, and it is taken as 1. A shift left or a sum keeps its result below
  2^22, so the float arithmetic is exact. The thread-position shift is unchanged. The star hash of `backgroundStarVertex` needs
  all 32 bits and has no bound, so it stays refused.
- Half values are declared `mediump float` (`declaredType`), at each declaration site, not highp. GLSL ES 1.00 guarantees
  `mediump` a 10-bit mantissa and a range of plus or minus 2^14; Metal's `half` has 10 bits and a range up to 65504. So the
  translation promises no more precision than Metal's half, and a value above 2^14 is not guaranteed on a device that
  implements only the minimum. Fragment shaders already default to mediump, so only vertex shaders change. Not measured
  against Metal; see the verdict doc's half-values section.
- A vertex function's `air.point_size` output is `gl_PointSize`, and only a float is accepted. The translator does not clamp
  the size: the GLES driver clamps it to its aliased point size range, which may differ from Metal's clamp. Not measured on a
  device. `air.any.v2i1` is GLSL `any`.
- Half-precision vertex attributes are refused, because the loader reads anything but
  float and i8 as a short.
- `BranchInst` is deprecated in LLVM 23.1.4, as in `air2cpu.cpp`. It is kept because the
  pinned revenant@llvm 23.1.3 cannot be checked on this machine.

## Checks

- `./xmakew l frameworks/Backports/tools/air2es_check.lua FOLDER [GLSLANG]` checks a
  folder written by `air2es METALLIB FOLDER`. It checks `library.json`, every
  function's reflection against its source, and the Appendix A limits. It runs
  glslangValidator as a separate gate, and reports how many functions pass each. A
  function counts only when both pass.
- `frameworks/Backports/tools/air2es_limits.lua` implements the Appendix A checks. The
  rules come from GLSL ES 1.00, Appendix A, section 4 (loops) and section 5 (indexing),
  revision 17.
- `./xmakew l -P frameworks/Backports frameworks/Backports/tests/air2es_test.lua` runs 15
  checker cases, the sampler checks, the capped-buffer test and the sampling test. The capped-buffer test translates
  `tests/air2es/capped_buffer.metallib` (compiled from `capped_buffer.metal` with the pinned Metal compiler), with the built
  `build/macosx/arm64/release/air2es`, and compares the folder with `capped_buffer.golden/`. It needs `callBlobVertex` to
  translate through its host cap (eight uniforms and a select chain) and `uncappedVertex` to be refused by name, since it has
  no cap. It is registered as the `air2es` suite of the backports tests.
- The sampling test translates `tests/air2es/sample_mac.metallib` (macOS, from `sample_mac.metal`). It checks that
  `sampleVertex` and `sampleFragment` are OK, that `sampleMinLodFragment` is refused by name, and that the `sampleFragment`
  folder matches `sample_mac.golden/`.
- The exit test translates `tests/air2es/exit_mac.metallib` (macOS, from `exit_mac.metal`): `exitVertex` and `exitFragment` are OK,
  and the `exitFragment` folder matches `exit_mac.golden/`. Its negative control for the oracle is the same source with the break's
  constant changed from 0.5 to 0.6.
- The derivative test translates `tests/air2es/deriv_mac.metallib` (macOS, from `deriv_mac.metal`): `derivVertex` and `derivFragment` are OK,
  and the `derivFragment` folder matches `deriv_mac.golden/`. Its negative control for the oracle is the same source with the `dfdx`
  scale changed from 16.0 to 8.0.
- The dfdy test translates `tests/air2es/dfdy_mac.metallib` (macOS, from `dfdy_mac.metal`): `dyFragment` and `dyNegFragment` are OK, and
  the `dyFragment` folder matches `dfdy_mac.golden/`. `air.dfdy.v2f32` maps to `-dFdy`: GL's y axis points up and Metal's points down,
  so the same derivative has the opposite sign. Its negative control for the oracle is the same folder with the `-` removed, which
  fails with a channel difference of 255 over 4,096 channels.
- The mask test translates `tests/air2es/mask_mac.metallib` (macOS, from `mask_mac.metal`): `maskVertex` and `maskFragment` are OK, and
  the `maskFragment` folder matches `mask_mac.golden/`. The loop index plus one is taken modulo eight, which is `and` in the IR: a bitwise
  and with `2^k - 1` of an integer with a known bound translates as `int(mod(float(x), 2^k))`, and the bound of a loop index is its trip
  count. Its negative control for the oracle is the same source with `(i + 2) % 8`, which fails with 9/255 over 4,096 channels.
- The flag test translates `tests/air2es/flag_mac.metallib` (macOS, from `flag_mac.metal`): `flagVertex` and `flagFragment` are OK, and the
  `flagFragment` folder matches `flag_mac.golden/`. The latch tests a header phi that is true on entry and false on the back edge, so the
  loop runs twice (`flagCycleOf`). Its negative control for the oracle is the same source with the second pass's factor 0.45 in place of
  0.4, which fails with 31/255 over 576 channels.
- The shared-member test translates `tests/air2es/shared_mac.metallib` (macOS, from `shared_mac.metal`): `sharedVertex` and `sharedFragment` are OK, and `sharedFragment` declares `u_viewport`, `u_parameters`, `lens_viewport` and `lens_parameters` at their own buffers. Members with the same name in two buffers of one kind get the argument's name as a prefix (`memberName`); `claimSlot` refuses a name claimed at another offset. The golden output is in `shared_mac.golden`.
- A block reached from both arms of a branch is emitted in each arm: `region` resets the visited set per arm, as `multiway` does. The
  Mac diamond's lens function needs this. No fixture covers it yet.
- The diamond's uniform sets are generated in scratch (not committed). They set the stone's `Uniforms` members under their GLES names (`viewport`, `parameters`, ...) and the lens's under the prefixed names (`u_viewport`, `u_parameters`, `lens_viewport`, `lens_parameters`). The harness SKIPs a case whose Metal output is blank.
- Negative control: replacing a loop bound with `int(inputTexture_size.x)` in the
  scaleAndBlur output keeps glslangValidator at exit 0, and the checker refuses it.
- The Telegram oracle is an external file, so the harness run on it is not part of CI.
  Whether it may run in CI is an owner decision.
