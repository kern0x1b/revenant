# surftool

The public surface of an SDK's `.swiftinterface`, read with **swift-syntax's `SwiftParser`**
(Apache-2.0, `https://github.com/swiftlang/swift-syntax`, taken at the path below) and printed as

    owner <TAB> member <TAB> argument labels <TAB> kind

The earlier regex gate (`api-invented`, since removed) read the same files with hand-written patterns, which miss what
a parser sees: an `associatedtype` witness printed as a `var`, a nested `typealias` printed as a
property, an enum `case`, an `init`, a `subscript`, a static in a constrained extension. Those are
exactly the rows it then called invented.

The walker also follows each interface's `@_exported import` lines and walks the modules they name,
so the oracle is the closure SwiftUI reaches rather than a list of modules written down here. Measured
on this tree: 241 rows before the parser, 205 after it, **201** once the re-export closure is followed
and the four CoreGraphics typealiases that no `.swiftinterface` declares are on the allow-list with that
reason.

It is a SwiftPM package because the gate itself must stay Lua-only and fast; the surface file is
generated by `bridge/surface-swiftui.sh` and read if it is there.

* `swift-syntax` — clone beside this package at `1a353aee69590104770295dce8b8fd7c2db0ba60`
  (`swift-DEVELOPMENT-SNAPSHOT-2026-09-21-a`), Apache-2.0. Nothing from it is vendored: it is a build
  dependency of this one tool, and it is not linked into Eidolon.

## What each artifact is, and which pair goes with which

`classify-gaps.lua` writes its report to stdout and its artifact with `-o`, and the artifact is
**regenerated byte for byte** from the gaps list — one line per row, `owner#name` then class, in the
input's own order:

    $ xmake l bridge/tools/classify-gaps.lua .agent-work/runs/gaps14.tsv -o bridge/gaps14-classified.tsv
    $ xmake l bridge/tools/classify-gaps.lua .agent-work/runs/gaps14.tsv -o .agent-work/runs/gaps14-check.tsv > /dev/null
    $ diff .agent-work/runs/gaps14-check.tsv bridge/gaps14-classified.tsv && echo empty
    empty

Four shapes are written by four tools, and pairing the wrong two used to print a green partition of
nothing. **`surf-diff.lua` reads three tab-separated columns per row, `owner` / `kind` / `name`, and
nothing else**; a file of any other shape is a hard error naming the file, the expected three and the
count found, because the sets it partitions would otherwise hold vacuously at `0 == 0`.

| artifact | columns | what it is | read by |
| --- | --- | --- | --- |
| `apple-26-surface.tsv` | 4 — owner, member, argument labels, kind | the **old** hand-written extractor's output | `api-surface.sh`, `gaps.lua` |
| `surface-26.2*.tsv` | **3** — owner, kind, name | `surf.lua`'s output: the surface of the SDK's interfaces | `surf-diff.lua`, `surf-check.lua` |
| `gaps*.tsv` | 1 — `Owner#name` | **gap rows**: what this tree declares no name for. 341 of them in `gaps14.tsv`, and *not* the 344 of the `|O\N|` above | read by eye, and classified by `classify-gaps.lua` |
| `ours*.tsv` | 4 — owner, kind, name, path | `ours.lua`'s output: this tree's own declarations | `ours-check.lua` |

**`ours.lua` writes four columns and `surf-diff.lua` reads three**, so the three-column *ours* file is made
by `ours3.lua`, which drops the path and collapses a row whose owner, kind and name repeat:

    xmake l bridge/tools/ours3.lua .agent-work/runs/ours13.tsv > .agent-work/runs/ours13-3col.tsv

`surf-diff-test.lua` covers the refusal: a 2-column file, a 4-column file, a 1-column *old* side, and an
empty *new* side with and without `--allow-empty-new`. **5/5.**

    $ xmake l bridge/tools/surf-diff.lua old.tsv new.tsv      # new.tsv has two columns
    …/new.tsv: line 1 has 2 tab-separated column(s), the 3 this diff reads are owner/kind/name; 1 line(s)
    in all (first at line 1). Refusing to read the file as the empty set: the partition below would hold
    vacuously. Use the artifact that has three columns (see bridge/tools/surftool/README.md …).
    $ echo $?
    1

One thing to know about what that refusal is *for*: `surf-diff.lua` was written to compare two
**extractions of the same interfaces**, the old hand-written one and the parser's. Run against Apple's
surface and this tree's declarations the sets partition exactly as the tool promises, and the classes are
then mostly a statement about two different corpora rather than about a lost extraction:

    |O| = 837   surface rows in OLD
    |N| = 8430   surface rows in NEW
    |O\N| = 344   |O\N| rows: moved 229  attribute 0  other 115
    |N\O| = 7937   |N\O| rows: gained
    identity over surface rows (not gap rows): |O|-|N| = -7593, |O\N| - |N\O| = -7593, classes: 229 + 0 + 115 = 344

**344 and 341 are two different sets that happen to be near each other, and nothing joins them:** 344 is
`|O\N|`, the OLD surface's rows the NEW one does not have, and 341 is the row count of the gaps list —
`classify-gaps.py`'s *gap rows*, which are the surface this tree declares no name for. Every report line
either tool prints now names the set it counts, so the two are not read as one.

Read `moved` there as "this leaf name is declared at another owner", not as "the rewrite moved it", and
read `other` as the interesting part: `Animatable#_makeAnimatable` (underscored machinery the interfaces
declare and this tree does not) and two bare `subscript` rows the old file names and the new one does not.

## Two things to know before you measure with this

**`bridge/fw/` is a generated, git-ignored copy, and the authority is the SDK path `surf.py` reads.** The
directory is not in the repository and not in any `.gitignore` inside it: `git check-ignore -v bridge/fw`
names **`.git/info/exclude:13`**, so it is excluded per clone — and in a worktree it is a **symlink**,
`bridge/fw -> ../../../../bridge/fw`, into another checkout's generated tree. Nothing measured from it is
a fact about this repository, and a `git clean -xdf` in the wrong place takes it with everything else.
The authority is named in the extractor: `surf.py` takes `SDK` from `$APPLE_26_SDK`, defaulting to
`~/Git/projects/ios/charon/.agent-work/sdk-26.2/iPhoneOS26.2.sdk`, and `surf-diff.py` reads the same root
for its `arm64e-apple-ios.swiftinterface` index. **A surface number is only comparable with another taken
from the same SDK root**, so `APPLE_26_SDK` is the variable to set rather than a path to edit; and where
the two disagree, the extractor's is right and `bridge/fw` is a convenience for the tools that want a
framework tree rather than interfaces.

**Patches 0006–0008 of the earlier series carry `wip:` subjects, and that history is exported rather than
rewritten.** Reading an exported patch as a claim about what ran would be wrong, and the series is not
amended to hide it: amending an exported series breaks every reference to it, and the honest form is the
commit's own message beside a note that says what it means. So: **read a series as a whole.** A `wip:`
commit says in its own subject line that its work did not run, and the commit that follows it is the one
that measured it. This series has no `wip:` subject, and `eidolon/AGENTS.md` asks for none — plain
imperative subject, no type prefix, no scope tag.
