# libSystem Backports

The iOS 6.1.3 dyld cache does not export `clock_getres`, `futimens`, `readlinkat`, `symlinkat`, `utimensat` or `_availability_version_check`. `SystemBackports` supplies the missing names for code linked against a newer SDK.

`clock_getres` forwards to the shared `apple-compat` implementation so the toolchain and Backports use one implementation.

The vibration of the phone is here too, because the UIKit feedback generators and the CoreHaptics backport both need it and it is the lowest layer every other library stands on. `RevenantVibratorIsAvailable` asks CoreMedia whether the phone has a vibrator, `RevenantVibratorPlay` asks AudioToolbox for a vibration with a pattern of on and off lengths in milliseconds, `RevenantVibratorPulse` plays the fixed vibration sound and `RevenantVibratorStop` stops a running vibration. What the iPhone 4S answers, and what could not be measured there, is in [the CoreHaptics reference](../CoreHaptics/README.md).

The `*at` file operations accept `AT_FDCWD` and directory descriptors. Absolute paths ignore `dirfd`. Relative paths with a directory descriptor validate the descriptor with `fstat`, reject non-directories with `ENOTDIR`, and resolve the directory path with `F_GETPATH` before invoking the iOS 6 path-based operation. This preserves the path selected at resolution time, but it is not atomic with a concurrent directory rename between `F_GETPATH` and the operation. The descriptor and the path are checked before the operation's other arguments, as the host system calls do: a null path is `EFAULT` first, a null `symlinkat` target is `EFAULT` before the path, a bad descriptor is `EBADF`, a non-directory descriptor with a relative path is `ENOTDIR`, and an empty relative path with a usable descriptor is `ENOENT`.

`readlinkat` delegates to `readlink`, preserving its byte count and non-terminating output behavior. `symlinkat` delegates to `symlink`, so an empty target creates a symlink the way the system call does.

`futimens` and `utimensat` translate `UTIME_NOW` and `UTIME_OMIT` into `setattrlist` and `fsetattrlist` requests: `UTIME_NOW` becomes one `gettimeofday` reading shared by both timestamps, `UTIME_OMIT` drops the attribute from the request, and an explicit timestamp is passed through with its nanoseconds. The attribute buffer carries `ATTR_CMN_MODTIME` before `ATTR_CMN_ACCTIME`, the ascending bit order `setattrlist` reads, and both omitted timestamps return success without a permission check once the file exists, as POSIX requires. `AT_SYMLINK_NOFOLLOW` on a symlink uses an `O_SYMLINK` descriptor and `fsetattrlist`; other paths go through `setattrlist`.

The host system calls accept an out-of-range `tv_nsec` and ignore unknown `utimensat` flags; this compatibility implementation enforces the POSIX `0..999999999` range and rejects flags other than `AT_SYMLINK_NOFOLLOW` with `EINVAL`. It validates the path first, so a real path error is still reported before the argument check. The host test therefore checks those cases against the required error rather than treating the observed host result as the expected behavior.

`_availability_version_check` answers the query compiler-rt uses for `@available` and `#available`. It reads `ProductVersion` from `/System/Library/CoreServices/SystemVersion.plist` once per process, encodes `major.minor.patch` as `((major & 0xffff) << 16) | ((minor & 0xff) << 8) | (patch & 0xff)`, and walks the request in order: an entry for another platform is skipped, the first entry for the running platform decides whether the release is at least the requested version, and a request that names no entry for the running platform is answered `true`. The current platform is macOS 1, iOS 2, tvOS 3, watchOS 4 and visionOS 11. Because the function exists, compiler-rt binds its weak import to it instead of parsing the plist itself.

Host behavior is compared against macOS system calls by `frameworks/Backports/tests/libsystem_at_test.lua`: explicit timestamps are compared with native `futimens` and `utimensat` results including nanoseconds, both-now timestamps are checked inside a measured window, the error precedence is compared call by call, and `_availability_version_check` is compared with the system function across version boundaries and mixed platform lists. The same fixture runs on an iPhone 4S with iOS 6.1.3 through `libsystem_at_device_test.lua`, linked against the built library: it checks the release boundary at 6.1.3, and the filesystem there stores timestamps in whole seconds, so the device checks compare the seconds and require a zero nanosecond field.
