# The 15.0 and 16.0 bands' ImageIO name constants

Twenty-four `kCGImage*` and `kIIO*` string constants in two objects, one object per release band because
`release-split` refuses an object whose symbols first appear in more than one release. Plain data a caller
looks a metadata key up with: the port answers it itself and the release is never asked.

## Every value was read, and the rule that works here fails on the rest of the group

Each value came from the host's own ImageIO with `dlsym`, as text and as bytes, through
`tests/backports/host/imageio-names`, which reads the PORT's values by linking the port's own object into a
pure C reader and comparing them against the host's.

The trailing component is the right rule for most of this slice — `kCGImagePropertyGroupImageIndexLeft` is
`GroupImageIndexLeft` — and it is wrong for the rest, in both directions:

- `kCGImagePropertyGroupTypeAlternate` is `Alternate`, not `GroupTypeAlternate`;
- `kCGImagePropertyGroupTypeStereoPair` is `StereoPair`;
- `kCGImagePropertyGroupImagesAlternate` is `GroupImages`, not `GroupImagesAlternate`;
- `kCGImagePropertyGroups` is `{Groups}`, with braces;
- `kCGImagePropertyHEIFDictionary` is `{HEIF}`, the same shape as the `{TGA}` and `{WebP}` of the 14.0 band;
- the three `kIIOMetadata_*Key` names are `CameraExtrinsics` and `CameraModel` — the symbol is
  `kIIOMetadata_CameraExtrinsicsKey` and the value is the bare noun.

Across the family's 64 absent names the measured value equals the symbol's own name in 7 cases and its
trailing component in 7, so **50 match neither**. The 15.0 band is the clearest case in the family of a
single prefix where most names follow one rule and four do not.

## The registry edit is line surgery, and the file is not a json.dump product

`absent_ImageIO.json` uses a mixed indentation — two spaces at the top level, three inside an entry — that
`json.dumps(indent=2)`, `indent=3` and the sorted variants all fail to reproduce byte for byte. A
round-trip rewrite would reformat all 967 lines to change 24 of them. This slice edits only the lines inside
the 24 target rows and asserts on the diff that nothing else moved: every removed line is one of the four
keys, every added line is one of those four or a row's `facts` line, and the counts are exactly 96 removed
and 120 added.

## The count does not depend on one spelling

The harness's two patterns take `CFStringRef const` and `const CFStringRef` in either order, and a permanent
plant writes a band in the other order and fails the run unless it is counted. Every band this run covers is
named in `objects.txt`, and a band left out of that file is not covered.
