# The 13.1, 14.0, 14.1, 16.3 and 26.0 bands' ImageIO name constants

Eighteen `kCGImage*` string constants in five objects, one object per release band because `release-split`
refuses an object whose symbols first appear in more than one release. Plain data a caller looks a metadata
key up with: the port answers it itself and the release is never asked.

## Every value was read, and a convention would have been wrong for most of these

Each value came from the host's own ImageIO with `dlsym`, as text and as bytes, through
`tests/backports/host/imageio-names`, which reads the PORT's values by linking the port's own object into
a pure C reader and comparing them against the host's. Across the family's 64 absent names the measured
value equals the symbol's own name in 7 cases and its trailing component in 7, so **50 match neither** — and
this slice contains both shapes, which is the point: `kCGImagePropertyWebPFrameInfoArray` is `FrameInfo`
and not `FrameInfoArray`, `kCGImagePropertyWebPDictionary` is `{WebP}`, `kCGImagePropertyTGACompression` and
`kCGImagePropertyOpenEXRCompression` are both plain `Compression`, while all four 14.1 names are their own
full symbol names.

## The registry edit is line surgery, and the file is not a json.dump product

`absent_ImageIO.json` uses a mixed indentation — two spaces at the top level, three inside an entry — that
`json.dumps(indent=2)`, `indent=3` and the sorted variants all fail to reproduce byte for byte. So a
round-trip rewrite would reformat all 967 lines to change 18 of them, which is what happened once in the
MediaPlayer family and hid the real change. This slice edits only the lines inside the 18 target rows and
asserts that every line outside them is byte-identical before and after.

## The control on merged rows runs in the harness

`merged-sample.sh` reads 40 of the 328 already-implemented constants, sampled with seed 20260929, through
the same reader and compares them with the port's own values: 40 examined, 40 match. Forty of 328, so a
defect confined to the other 288 would not show.

## Two defects this slice's generalisation exposed, kept where they can be read

`sed` with a glob and no `-i` PRINTS the files and edits nothing — the first mutant of this slice found
zero markers for exactly that reason, after the copy had already succeeded. And `clang -c` with a single
`-o` for several inputs is invalid, so the harness compiles each source apart and links the reader with
all of them, which is also what the port does.
